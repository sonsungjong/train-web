# [4과목] 서버 프로그램 구현

## 1. 모듈 (Module)과 성능 평가
소프트웨어 설계에서 기능 단위로 분해하고 추상화되어 재사용 및 공유 가능한 수준으로 만들어진 단위입니다. 모듈의 독립성은 **결합도(Coupling)**와 **응집도(Cohesion)**에 의해 측정됩니다.
* **좋은 설계의 조건:** 결합도는 약하게(낮게), 응집도는 강하게(높게), 모듈 크기는 작게!

### 결합도 (Coupling) - 낮을수록 좋음
모듈 간에 상호 의존하는 정도입니다.
*(암기 팁: 데·스·제·외·공·내 - 우측으로 갈수록 결합도 높아짐/안 좋음)*
* **데이터(Data):** 모듈 간에 매개변수로 데이터만 주고받는 상태 (가장 좋음)
* **스탬프(Stamp):** 배열이나 레코드 등의 자료 구조가 전달되는 상태
* **제어(Control):** 제어 신호(Control Signal)를 전달하여 통제하는 상태
* **외부(External):** 어떤 모듈에서 선언한 데이터를 외부의 다른 모듈에서 참조하는 상태
* **공통(Common):** 전역 변수를 참조하고 갱신하는 상태
* **내용(Content):** 다른 모듈 내부에 있는 변수나 기능을 직접 참조/수정하는 상태 (가장 나쁨)

### 응집도 (Cohesion) - 높을수록 좋음
모듈 내부의 구성 요소들이 서로 관련되어 있는 정도입니다.
*(암기 팁: 우·논·시·절·통·순·기 - 우측으로 갈수록 응집도 높아짐/좋음)*
* **우연적(Coincidental):** 아무 관련 없는 요소들이 모인 상태 (가장 나쁨)
* **논리적(Logical):** 유사한 성격을 갖거나 특정 형태로 분류되는 처리 요소들이 모인 상태
* **시간적(Temporal):** 특정 시간에 처리되어야 하는 활동들을 모은 상태
* **절차적(Procedural):** 모듈 안의 다수 관련 기능들이 순차적으로 수행되는 상태
* **통신적(Communicational):** 동일한 입출력을 사용하여 서로 다른 기능을 수행하는 상태
* **순차적(Sequential):** 한 활동으로부터 나온 출력값을 다음 활동의 입력 데이터로 사용하는 상태
* **기능적(Functional):** 모듈 내부의 모든 기능이 단일한 목적을 위해 수행되는 상태 (가장 좋음)

## 2. 객체지향 (Object-Oriented) 
현실 세계의 개체(Entity)를 속성과 메서드가 결합된 형태의 객체(Object)로 표현하는 기법입니다.

### 객체지향의 특징 (캡.상.다.정.추)
* **캡슐화 (Encapsulation):** 속성과 관련된 연산을 하나로 묶고, 외부의 불법적인 접근을 막는 것 (정보 은닉).
* **상속 (Inheritance):** 상위 클래스의 속성과 메서드를 하위 클래스가 물려받는 것.
* **다형성 (Polymorphism):** 하나의 메시지에 대해 각 객체가 고유한 방식으로 응답할 수 있는 능력 (오버로딩, 오버라이딩).

### 객체지향 설계 5원칙 (SOLID) ★매우 중요★
* **SRP (단일 책임 원칙):** 객체는 단 하나의 책임만 가져야 한다.
* **OCP (개방-폐쇄 원칙):** 기존의 코드를 변경하지 않고 기능을 추가할 수 있어야 한다. (확장에는 열려있고, 수정에는 닫혀있음)
* **LSP (리스코프 치환 원칙):** 자식 클래스는 부모 클래스의 역할을 완벽히 대체할 수 있어야 한다.
* **ISP (인터페이스 분리 원칙):** 자신이 사용하지 않는 인터페이스와 의존 관계를 맺거나 영향을 받지 않아야 한다.
* **DIP (의존 역전 원칙):** 의존 관계를 맺을 때 변화하기 쉬운 것보다는 변화하기 어려운 것(추상 클래스, 인터페이스)에 의존해야 한다.

## 3. GoF 디자인 패턴 (Design Pattern) ★매우 중요★
소프트웨어 설계 시 자주 발생하는 문제들을 해결하기 위해 고안된 재사용 가능한 설계 모형입니다. (총 23개)
*(암기 팁: 생성, 구조, 행위 - 생구행)*

### 생성 패턴 (Creational) - 5개
객체 생성에 관련된 패턴입니다. *(암기 팁: 빌·프·팩·앱·싱)*
* **Builder:** 복잡한 인스턴스를 조립하여 만드는 구조.
* **Prototype:** 원본 객체를 복제하여 생성.
* **Factory Method:** 객체 생성을 서브 클래스에서 위임하여 처리 (가상 생성자).
* **Abstract Factory:** 구체적인 클래스에 의존하지 않고 인터페이스를 통해 서로 연관/의존하는 객체들의 그룹을 생성.
* **Singleton:** 어떤 클래스의 인스턴스가 오직 하나임을 보장.

### 구조 패턴 (Structural) - 7개
클래스나 객체를 조합해 더 큰 구조를 만드는 패턴입니다. *(암기 팁: 어·브·컴·데·퍼·플·프)*
* **Adapter:** 호환성이 없는 기존 클래스의 인터페이스를 변환하여 재사용.
* **Bridge:** 구현부에서 추상층을 분리하여 각자 독립적으로 확장.
* **Composite:** 객체들의 관계를 트리 구조로 구성하여 부분-전체 계층을 표현.
* **Decorator:** 객체의 결합을 통해 기능을 동적으로 유연하게 확장.
* **Facade:** 복잡한 서브 클래스들을 피해 더 상위에 인터페이스를 구성 (단순한 인터페이스 제공).
* **Flyweight:** 인스턴스가 필요할 때마다 생성하지 않고 가능한 한 공유해서 사용 (메모리 절약).
* **Proxy:** 특정 객체로의 접근을 제어하기 위한 대리자 역할.

### 행위 패턴 (Behavioral) - 11개
객체나 클래스 사이의 알고리즘이나 책임 분배에 관련된 패턴입니다.
* **주요 패턴:** Observer(상태 변화 시 객체들에 통보), State(상태에 따라 행위 변경), Strategy(알고리즘 캡슐화 및 교체), Template Method(상위에서 뼈대 정의, 하위에서 세부 구현), Command(요청을 캡슐화), Iterator(내부 노출 없이 순차 접근) 등.
