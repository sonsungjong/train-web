# [7과목] 애플리케이션 테스트 관리

## 1. 소프트웨어 테스트 기본 원칙 ★중요★
시험에서 다음 원칙에 대한 설명을 주고 무엇을 의미하는지 묻는 문제가 자주 나옵니다.
* **결함 집중 (Defect Clustering):** 애플리케이션 결함의 대부분은 소수의 특정 모듈에 집중되어 발생함. (파레토 법칙, 80대 20 법칙)
* **살충제 패러독스 (Pesticide Paradox):** 동일한 테스트 케이스로 반복 실행하면 더 이상 새로운 결함을 발견할 수 없음. (주기적인 테스트 케이스 리뷰와 개선 필요)
* **오류-부재의 궤변 (Absence-of-Errors Fallacy):** 결함을 모두 제거했더라도 사용자의 요구사항을 충족하지 못하면 해당 소프트웨어는 품질이 높다고 볼 수 없음.
* **완벽한 테스팅은 불가능:** 프로그램의 모든 내부 경로와 입력의 조합을 100% 완벽하게 테스트하는 것은 불가능함.

## 2. 화이트박스 테스트 (White Box Testing)
개발자 관점에서 소스 코드의 **내부 논리적인 구조와 동작**을 꼼꼼하게 검사하는 구조 기반 테스트입니다.

### 화이트박스 테스트 종류
* **구문(Statement) 커버리지:** 코드의 모든 '문장'이 최소 한 번 이상 실행되도록 설계.
* **결정/분기(Decision/Branch) 커버리지:** 조건식의 전체 결과가 참(True)과 거짓(False)을 각각 최소 한 번 이상 갖도록 설계.
* **조건(Condition) 커버리지:** 조건식 '내부의 개별 조건'들이 참과 거짓을 각각 최소 한 번 이상 갖도록 설계.
* **조건/결정(Condition/Decision) 커버리지:** 개별 조건식과 전체 조건식이 모두 참/거짓을 한 번 이상 갖도록 설계.
* **기본 경로 검사 (Base Path Testing):** 흐름도를 이용해 논리적 복잡성을 측정하여 독립적인 경로(순환 복잡도)를 도출하고 테스트.

## 3. 블랙박스 테스트 (Black Box Testing)
사용자 관점에서 프로그램의 내부 구조를 보지 않고, **입력에 대한 올바른 출력이 나오는지 기능(명세서)을 검사**하는 테스트입니다.

### 블랙박스 테스트 종류 ★매우 중요★
*(암기 팁: 동·경·원·오·비)*
* **동치 분할 검사 (Equivalence Partitioning):** 입력 데이터의 영역을 유효한 값과 무효한 값으로 나누어 대표값을 바탕으로 테스트.
* **경계값 분석 (Boundary Value Analysis):** 입력 조건의 경계값을에서 오류가 발생할 확률이 높다는 점을 이용해 경계값을 테스트 케이스로 선정.
* **원인-효과 그래프 (Cause-Effect Graphing):** 입력 데이터(원인)와 출력 결과(효과) 간의 관계를 논리적 그래프로 표현하여 검사.
* **오류 예측 검사 (Error Guessing):** 테스터의 감각과 경험을 바탕으로 과거의 경험이나 직관을 사용해 테스트.
* **비교 검사 (Comparison Testing):** 여러 버전의 프로그램에 동일한 테스트 자료를 제공하여 동일한 결과가 출력되는지 검사.

## 4. 개발 단계에 따른 테스트 (V-모델)
소프트웨어 개발 단계(SDLC)에 맞추어 검증하는 테스트 레벨입니다.
*(순서 암기: 단 ➔ 통 ➔ 시 ➔ 인)*

1. **단위 테스트 (Unit Test):** 코딩 직후 모듈이나 컴포넌트 단위로 수행하는 테스트. (주로 화이트박스)
2. **통합 테스트 (Integration Test):** 모듈들을 결합하여 시스템을 완성시키는 과정에서 인터페이스 연동 오류를 찾는 테스트.
3. **시스템 테스트 (System Test):** 개발된 소프트웨어가 해당 컴퓨터 시스템에서 완벽하게 수행되는지 점검.
4. **인수 테스트 (Acceptance Test):** 소프트웨어가 사용자의 요구사항을 충족하는지 최종 확인.
    * **알파 테스트:** 개발자 환경에서 사용자가 통제하에 수행.
    * **베타 테스트:** 실제 사용자 환경에서 다수의 사용자가 통제 없이 수행.

## 5. 통합 테스트의 종류 (하향식 vs 상향식) ★중요★
* **하향식 통합 (Top-Down):** 제어의 상위 모듈에서 하위 모듈 방향으로 통합. 
    * 아직 개발되지 않은 하위 모듈을 대체하기 위해 **스텁(Stub)** 이라는 가짜 모듈을 사용함.
* **상향식 통합 (Bottom-Up):** 하위 모듈에서 상위 모듈 방향으로 통합.
    * 모듈들을 클러스터로 결합하고, 제어를 위해 **드라이버(Driver)** 라는 가짜 프로그램을 작성함.
    *(암기 팁: 하-스, 상-드)*
* **샌드위치 통합:** 하향식과 상향식을 결합한 하이브리드 방식.

## 6. 테스트 오라클 (Test Oracle)
테스트의 결과가 참인지 거짓인지를 판단하기 위해 사전에 정의된 참값(Expected Result)을 입력하여 비교하는 기법입니다.
* **참(True) 오라클:** 모든 입력값에 대해 기대하는 결과를 생성함으로써 발생된 오류를 모두 검출할 수 있는 오라클.
* **샘플링(Sampling) 오라클:** 특정한 몇 개의 입력값에 대해서만 기대하는 결과를 제공하는 오라클.
* **휴리스틱(Heuristic) 오라클:** 샘플링 오라클을 개선한 것으로, 특정 입력값은 올바른 결과를 제공하고, 나머지 값들은 휴리스틱(직관, 추정)으로 처리.
* **일관성 검사(Consistent) 오라클:** 애플리케이션 변경이 있을 때, 수행 전과 후의 결괏값이 동일한지 확인.
