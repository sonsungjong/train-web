# [6과목] 화면 설계

## 1. UI (User Interface)와 UX (User Experience)
* **UI (사용자 인터페이스):** 사람과 시스템(컴퓨터, 모바일 등) 간에 의사소통을 할 수 있도록 만들어진 물리적, 가상적 매개체. (버튼, 레이아웃, 화면 구조 등)
* **UX (사용자 경험):** 사용자가 시스템이나 서비스를 이용하면서 느끼고 생각하는 총체적인 경험. UI를 포함하는 더 넓은 개념.

## 2. 화면 설계 산출물 (UI 설계 도구) ★매우 중요★
시험에서 각 산출물의 설명을 주고 무엇인지 맞추는 단답형 문제가 자주 출제됩니다. 

| 종류 | 설명 및 특징 |
| :--- | :--- |
| **와이어프레임 (Wireframe)** | 기획 단계의 초기에 제작하는 **화면 단위의 뼈대(레이아웃) 스케치**. 선과 도형으로 화면의 구조만 단순하게 표현. |
| **목업 (Mockup)** | 와이어프레임보다 좀 더 실제 화면과 유사하게 만든 **정적인 형태의 모형**. 시각적인 디자인(색상, 폰트 등)이 적용되지만, 실제로 클릭되거나 동작(동적 기능)하지는 않음. |
| **스토리보드 (Storyboard)** | 와이어프레임에 콘텐츠에 대한 설명, 페이지 간 이동 흐름(인터랙션) 등을 추가한 문서. **디자이너와 개발자가 최종적으로 참고하는 작업 지침서**. |
| **프로토타입 (Prototype)** | 와이어프레임이나 스토리보드에 인터랙션을 적용하여 실제 구현된 것처럼 **테스트가 가능한 동적인 형태의 모형**. 사용성 테스트나 요구사항 검증을 위해 제작. |
| **유스케이스 (Use Case)** | 사용자 측면에서의 요구사항으로, 사용자가 원하는 목표를 달성하기 위해 수행할 내용을 기술한 것. |

## 3. UI 설계 프로세스
일반적으로 다음과 같은 흐름으로 진행됩니다.
1. **문제 정의:** 시스템의 목적과 사용자의 요구사항 파악.
2. **사용자 모델 조사:** 타겟 사용자의 특성, 환경, 숙련도 등 분석.
3. **작업 분석:** 사용자가 시스템을 통해 수행할 작업의 순서와 절차 분석.
4. **컴퓨터 오브젝트 및 기능 정의:** 작업에 필요한 화면 요소와 기능 정의.
5. **사용자 인터페이스 정의:** 실제 화면 디자인 및 레이아웃 설계.
6. **디자인 평가:** 설계된 UI의 사용성 및 문제점 평가.

## 4. 웹/모바일 화면 설계 시 고려사항
* **반응형 웹 (Responsive Web):** 디스플레이의 종류(PC, 태블릿, 스마트폰 등)에 따라 화면의 크기가 자동으로 최적화되어 조절되는 웹 구현 기법.
* **크로스 브라우징 (Cross Browsing):** 크롬, 엣지, 사파리 등 서로 다른 브라우저에서도 동일한 화면과 기능을 제공하도록 하는 웹 표준 기술.
* **웹 접근성 (Web Accessibility):** 장애인이나 고령자 등 신체적/환경적 제약이 있는 사용자도 웹 사이트에서 제공하는 정보를 동등하게 접근하고 이해할 수 있도록 보장하는 것.

## 5. HCI (Human Computer Interaction)
사람과 컴퓨터 사이의 상호작용을 연구하여, 사람들이 컴퓨터 시스템을 더 쉽고 편리하게 사용할 수 있도록 시스템을 디자인하고 평가하는 학문입니다.

## 6. 감성공학 (Kansei Engineering)
인간의 감성(느낌, 이미지 등)을 정량적으로 측정하고 분석하여, 이를 제품이나 환경 설계에 반영하는 기술입니다. 인간의 삶의 질을 향상시키는 것이 목적입니다.
