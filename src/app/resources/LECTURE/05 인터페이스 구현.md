# [5과목] 인터페이스 구현

## 1. 인터페이스 설계 및 데이터 표준
송신 시스템과 수신 시스템 간의 데이터 교환을 위해 데이터 포맷, 통신 규칙, 보안 등을 정의하는 과정입니다.

* **인터페이스 명세서:** 시스템 간 인터페이스 방식, 송수신 데이터 명세, 오류 처리 방안 등을 상세히 작성한 문서.
* **데이터 포맷:**
    * **JSON:** 속성-값 쌍(Key-Value) 형태, 가볍고 파싱이 빠름. 웹/모바일, AJAX에서 주로 사용.
    * **XML:** 태그(Tag)를 사용하여 데이터를 구조화. 다소 무겁지만 확장성과 호환성이 좋음.
    * **YAML:** 사람이 읽기 쉬운 데이터 직렬화 양식. 들여쓰기로 데이터의 구조를 구분함.

## 2. 인터페이스 데이터 보안 ★중요★
인터페이스 과정에서 데이터 탈취나 위변조를 막기 위해 네트워크 구간 및 데이터 자체에 보안을 적용합니다.

### 1) 네트워크 구간 보안 (전송 구간 암호화)
* **IPSec (IP Security):** 네트워크 계층(3계층)에서 IP 패킷 단위로 인증, 데이터 암호화, 키 관리를 수행하는 보안 프로토콜.
* **SSL/TLS:** 전송 계층(4계층)과 애플리케이션 계층(7계층) 사이에서 클라이언트와 서버 간의 안전한 통신을 지원하는 프로토콜.
* **S-HTTP:** 웹 상에서 네트워크 트래픽을 암호화하는 프로토콜 (HTTP 메시지 자체를 암호화).

### 2) 데이터 암호화 알고리즘
*(암기 필수: 양방향/단방향, 대칭키/비대칭키 구분)*
* **양방향 암호화 (복호화 가능):**
    * **대칭키 (비밀키):** 암호화와 복호화에 **같은 키** 사용. 속도가 빠르지만 키 관리(전달)가 어려움.
        * 종류: DES, AES(미국 표준), SEED(국산), ARIA(국산), IDEA 등
    * **비대칭키 (공개키):** 암호화(공개키)와 복호화(개인키)에 **다른 키** 사용. 키 관리가 쉽지만 속도가 느림.
        * 종류: RSA, ECC 등
* **단방향 암호화 (해시, 복호화 불가능):** 패스워드 저장, 무결성 검증 등에 사용. 임의의 길이의 입력 데이터를 고정된 길이의 해시값으로 변환.
    * 종류: MD5, SHA-1, SHA-256, HAS-160 등

## 3. 인터페이스 구현 검증 (테스트 자동화 도구) ★매우 중요★
인터페이스가 정상적으로 동작하는지 확인하기 위해 사용하는 테스트 자동화 프레임워크 및 도구들입니다. (영어 명칭과 특징을 매칭할 수 있어야 합니다)

| 도구 명칭 | 특징 및 설명 |
| :--- | :--- |
| **xUnit** | Java(JUnit), C++(CppUnit), .NET(NUnit) 등 **다양한 언어를 지원하는 단위 테스트** 프레임워크 |
| **STAF** | 서비스 호출, 컴포넌트 재사용 등 **다양한 환경(분산 환경)을 지원**하는 크로스 플랫폼 테스트 프레임워크 |
| **FitNesse** | **웹 기반** 테스트 케이스 설계, 실행, 결과 확인 등을 지원하는 테스트 프레임워크 |
| **NTAF** | FitNesse의 장점(협업)과 STAF의 장점(재사용 및 확장성)을 통합한 **NHN(네이버)**의 테스트 자동화 프레임워크 |
| **Selenium** | **웹 애플리케이션 테스트**를 위한 프레임워크. 다양한 브라우저 및 언어 지원 |
| **watir** | **Ruby(루비)** 언어 기반의 웹 애플리케이션 UI 테스트 자동화 도구 |

## 4. APM (Application Performance Management)
인터페이스 및 애플리케이션의 성능을 모니터링하고 관리하는 도구입니다.
* 데이터베이스 접속, 자원 사용량, 응답 시간 등을 시각적으로 확인하여 성능 장애 요인을 분석합니다.
* 종류: 스카우터(Scouter), 제니퍼(Jennifer) 등
